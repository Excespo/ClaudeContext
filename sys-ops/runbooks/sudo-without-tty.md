# Claude 需要 root 时怎么办（本机 sudo 拿不到密码）

## 症状
Claude 在 Bash 工具里执行 `sudo ...`，命令挂起或直接失败；用户在 Terminal.app 里先跑 `sudo -v` 也不管用。

## 机制
两层原因，缺一不可地导致失败：
1. Bash 工具没有分配 tty，`sudo` 无法弹出密码提示。
2. macOS 的 sudo 默认启用 `tty_tickets`，凭据缓存按 tty 隔离——用户在 Terminal.app 里 `sudo -v` 拿到的 ticket 绑定在那个 tty 上，传不到 Claude 的无 tty 会话。

另有一层策略约束：`settings.json` 已经 deny `Bash(sudo *)`。

## 处置
| 步骤 | 命令 | 副作用 | 失败时 |
|---|---|---|---|
| 1 探测 | `sudo -n true` | 只读 | 失败即确认拿不到 root，进入第 2 步，**不要**让用户去试 `sudo -v` |
| 2 写脚本 | 把需要 root 的动作写成一个脚本，放当前工作目录 | 创建文件 | — |
| 3 加护栏 | 脚本开头校验身份与前提：`[ "$(id -u)" = 0 ]`、目标路径存在性、卷是否可写、`set -euo pipefail` | 只读 | 校验不过就退出并打印原因 |
| 4 交给用户 | 用户在真终端里 `sudo bash <脚本>` | 有副作用，由用户执行 | 脚本里逐条 echo 命令与退出码，便于事后追溯 |

## 校验
脚本必须自己输出：执行了哪些命令、每条的退出码、实测效果（文件是否存在、权限是否变化）。不要以「没报错」作为成功判据。

## 已知坑
- 不要试图用 `osascript` 弹密码框绕过；密码会进入进程参数与日志。
- 不要在脚本里嵌入密码，也不要要求用户把密码贴进对话。
