# pass@k 的正确算法与 repeats 的关系

来源：2025-04 的三次对话（本人连续纠错）。证据等级：**A，结论可回 CodeEval / Chen et al. 2021 核对**。

## 正确的估计量

pass@k 是「从 n 个采样里随机取 k 个，至少有一个正确」的概率。逐题算完再对题取平均：

```
pass@k = 1 − C(n − c, k) / C(n, k)        # c = 该题正确的采样数
```
`n < k` 时该题记 0（或跳过）。这是 Chen et al. 2021 的无偏估计量，HF `evaluate` 的 CodeEval 里叫 `estimate_pass_at_k`，实现上用对数累乘避免组合数溢出。

**三种错误写法**（都在那几次对话里出现过）：

| 写法 | 错在哪 |
|---|---|
| `sum(correct) >= k` | 返回布尔，且语义是「至少 k 个对」，不是「k 次里至少一个对」 |
| `1 − ((n−c)/n)**k` | 有放回抽样的近似，n 小时偏差明显；无偏版是超几何的 |
| 遍历 `predictions` 当成多题 | 数据结构错。`predictions` 是嵌套的：每题一个长度 n 的采样列表 |

## repeats 与 k 的搭配

- `do_sample: false` + `repeats: 1` + `k: [1]` —— **合法**。贪心解码是确定性的，pass@1 就是「最优解是否通过」，重复采样没有意义。
- 采样解码时的 pass@1 —— 需要多次采样求期望（c/n），一次采样只是它的高方差估计。
- humaneval_64：`repeats: 64`、`temperature: 0.2`、`k: [2,8,16,32,64]`
- math_500：`repeats: 16`、`temperature: 0.6`、`top_p: 0.95`、`k: [1,2,4,8]`

**经验规则**：`k` 的最大值不能超过 `repeats`；`repeats` 至少取 `2×max(k)` 才能让估计量方差可接受。
